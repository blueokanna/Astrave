# 性能测量

## TCP 缓冲调整的 Windows 回环实测

2026 年 11 月 20 日，在同一台 Windows 10 x64、Intel Core i7-11850H 机器上对比两份本地 Release，工具链为 Rust 1.95.0 和 Dart 3.13.7。每个版本运行三轮，每轮由一个客户端注册 128 条 TCP 隧道，开启 TCP 多路复用，关闭 TLS。同一条隧道建立 64 条连接，每条先完成一次往返，再采样两个进程的内存。随后用其中 8 条连接并发传输，每条完成 512 次 64 KiB 回显并逐字节校验，双向合计 512 MiB。内存值不含回显服务、压测程序和 Flutter 图形界面。

| 三轮中位数 | 调整缓冲前 | 调整缓冲后 |
| --- | ---: | ---: |
| 客户端工作集 | 39.94 MiB | 11.86 MiB |
| 服务端工作集 | 41.13 MiB | 13.12 MiB |
| 客户端私有字节 | 35.31 MiB | 6.81 MiB |
| 服务端私有字节 | 36.31 MiB | 8.11 MiB |
| 校验通过的双向吞吐 | 455.4 MiB/s | 443.4 MiB/s |

吞吐中位数下降 2.6%。旧版三轮为 431.1–458.7 MiB/s，新版为 427.9–457.3 MiB/s，区间重叠。广域网、TLS 和长期满载需要各自的实测。工作集衡量驻留内存，私有字节衡量进程私有提交量，两列应分别解读。

每轮转发结束后，每个管理接口先预热 5 次，再计时 100 次。下表分别取三轮 p50 和 p95 的中位数，包含 Basic 认证、序列化、回环传输和 Dart 的 JSON 解码。

| 管理请求 | 优化前 p50 / p95（µs） | 优化后 p50 / p95（µs） |
| --- | ---: | ---: |
| 系统概览 | 363 / 458 | 188 / 354 |
| 隧道第 4 页，每页 20 行，名称筛选命中全部 128 条 | 397 / 511 | 252 / 394 |
| 客户端页，1 个在线客户端 | 342 / 437 | 175 / 226 |

## 流量历史按需分配的复测

这次以已使用 32 KiB 复制缓冲的版本为基线，保留旧二进制，再与最终构建在同一台 Windows 机器上各跑三轮上述负载。采样时 64 条已预热连接仍然打开。流式转发在连接结束后记账，因此本次内存样本覆盖隧道已注册、尚未首次记账的阶段。

| 三轮中位数 | 按需分配前 | 按需分配后 |
| --- | ---: | ---: |
| 服务端工作集 | 13.14 MiB | 12.96 MiB |
| 服务端私有字节 | 8.11 MiB | 7.79 MiB |
| 校验通过的双向吞吐 | 410.8 MiB/s | 432.8 MiB/s |
| 系统概览 p50 / p95 | 206 / 306 µs | 219 / 376 µs |
| 隧道筛选分页 p50 / p95 | 261 / 412 µs | 268 / 410 µs |
| 客户端分页 p50 / p95 | 197 / 282 µs | 175 / 262 µs |

最终三轮吞吐范围分别为 399.4–410.9 和 419.8–454.5 MiB/s。开发期间另一组各三轮的对照中，中位数为 417.7 和 420.0 MiB/s，且区间重叠。两批计时存在波动。可以直接从代码核算的收益是，每条尚未首次记账的隧道减少四次堆分配和 496 字节计数数组，不含分配器开销。128 条这样的隧道可省 62 KiB 计数存储。进程内存的变化还包含其他分配及操作系统因素。

最终六轮的原始 JSON 行保存在源码目录 `docs/benchmarks/traffic-history-windows-before.jsonl` 和 `docs/benchmarks/traffic-history-windows-after.jsonl` 中。

## 时间和空间复杂度

| 操作 | 时间 | 额外空间与上限 |
| --- | --- | --- |
| TCP 转发 `N` 字节 | O(N) | 每条活动转发在每个进程使用两个 32 KiB 复制缓冲，原为两个 256 KiB。内核、TLS 和多路复用的缓冲另计。 |
| UDP 转发 `B` 字节、`P` 个本地对端 | 每个转发报文 O(B)，查找对端平均 O(1) | O(P × 接收缓冲大小 + 队列槽数 × 载荷大小)。每个转发器最多 1,024 个对端，每条通道最多 1,024 槽，载荷容量约 2 MiB 以内，元数据另计。出站队列已满时在复制前丢弃。 |
| 数据连接池 | 入队、出队预期 O(1) | 空间随池容量和等待任务数增长。新连接唤醒一个等待者，关闭时唤醒全部。 |
| 配置热重载，旧隧道 `A` 条、新隧道 `B` 条、变更 `D` 条 | 字段长度有界时预期 O(A+B+D log D) | O(A+D)，保留一份旧名称索引和排序后的差异。 |
| 注册及按名查找 `T` 条隧道 | O(log T) 次名称比较 | 有序注册表占 O(T)，请求分页时直接按名称遍历。 |
| 查询 `K` 行隧道 | 名称和筛选串长度有界时 O(T+K)。名称长 `L`、筛选串长 `Q` 时，逐字节窗口查找的最坏时间为 O(T × L × Q)。 | 返回记录占 O(K)。为了返回准确总数仍需计数全部命中，仅为当前页构造详情和读取统计。 |
| 系统概览 | 固定历史窗口下，预期 O(F+Y)，`F` 为保留的离线客户端数，`Y` 为协议种数 | 返回计数占 O(Y)。离线客户端及已关闭隧道历史分别最多保留 1,024 条，按关闭时间淘汰最早记录，有序索引操作 O(log 1024)。 |
| 客户端列表，共 `C` 个在线及保留的离线客户端 | 字段长度有界时最坏 O(C log C + Tₚ)，`Tₚ` 为本页客户端拥有的隧道数 | 临时空间 O(C+K)。在线优先，同组按代理标识及会话标识排序。 |
| 隧道流量历史，窗口含 `H` 个时段 | 同时段累加预期 O(1)，跨时段清理最坏 O(H)，读取历史 O(H)。 | `T` 条保留记录中有 `A` 条产生过非零计数时，隧道指标共占 O(T + A × H)。首次记录流量前不分配历史数组。图表在锁内复制最多 24 对收发计数，释放锁后生成时间标签。 |
| 桌面隧道列表，配置 `T` 条 | 首屏构造可见区和预加载区所需的 `V` 行，时间 O(V)。 | 完整配置占 O(T)，可见区和预加载区行组件额外占 O(V)。编辑或选取文本时保留的行另计。 |
| 桌面活动日志 | 追加、淘汰均摊 O(1)，无筛选时读取 `V` 个可见行的时间为 O(V)。筛选需扫描保留文本。 | Rust 待取队列和 Flutter 显示队列各保留最多 500 条。无筛选时行索引额外占 O(1)，筛选命中 `M` 条时占 O(M) 个引用。 |

Dart 微基准预置 500 行。执行 10 万次淘汰并追加，普通列表耗时中位数为 152.2 ms，环形队列为 1.09 ms。连续 1 万次无筛选读取 24 个可见行，先复制全部 500 个引用耗时 22.88 ms，直接索引耗时 0.84 ms。这里测量集合操作，Flutter 布局、绘制及桌面进程内存需另行采样。

## 复现

```sh
cargo build --locked --release -p astrave-client -p astrave-server
dart scripts/benchmark.dart target/release
dart scripts/benchmark.dart --logs
```

将第一条 Dart 命令的目录换为保留的旧版二进制目录，即可同负载对比。每轮使用新的回环端口和配置，校验回显内容以及第 4 页第一条隧道名称。进程内存采样支持 Windows。
